# Technical review — October 2026

This review checks the actual source and reproducible tests. Scores describe suitability as a portfolio project, not a production certification.

## Confirmed findings

Default malformed-input errors returned framework HTML internals; unauthenticated order data was reachable if the local API was exposed.

## Existing strengths

Server-owned pricing and transactional order/item persistence.

## Changes and evidence

- Prices are loaded from products on the server; the order and items are written in one transaction.
- Default loopback binding and small JSON error responses reduce accidental exposure of the local API.

Existing product/order tests, malformed-JSON regression, response contract and prior-schema upgrade checks.

## Conditional risks and remaining work

Order lookup is not owner-authorized. Loopback is a deployment boundary, not a substitute for customer authentication.

- No payment, delivery integration or authenticated customer accounts. Order detail endpoints are not protected for public exposure and include customer information.
- Request array/field bounds and durable customer authorization are required before a public store deployment.

Before: **5/10**. After this pass: **5.5/10**. The difference is justified by the concrete fixes/tests above; unchanged grades mean the core design has not changed.
